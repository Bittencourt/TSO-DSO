# Quick Task 260825-w5b: IEEE-13 ADMM knife-edge canary test

## Why

`.planning/debug/resolved/ieee13-admm-numerical-error.md` (resolved 2026-08-25) pinned that the
IEEE-13 ADMM mid-loop DSO-OPT SOCP sits on a genuine numerical knife-edge at iteration 28 (ρ=200,
one τ=2 doubling from ρ₀=100). Which side of the edge a given build lands on is decided by
floating-point/codegen perturbation (an unreachable `include`, a Julia patch bump), never by
run-to-run noise — each (tree × Julia version) pair is deterministic. The production fix
(`solve_dso!`'s mid-loop branch now routed through `solve_with_retry!`, RESET-01) makes every
toolchain tested converge, which is exactly why nothing currently in the suite would notice a
FUTURE flip: it cost a 225-commit `git bisect` to attribute this time, and the bisect result was
actively misleading without a manual A/B (the first-bad commit was purely additive and never
called on the ADMM path). STATE.md carries this as backlog item C4. This task closes it: a
dedicated, always-on regression test that pins the invariants which held across every measured
environment, and reports (without over-asserting) the one signal that genuinely differs by
toolchain — whether the conditioning ladder had to fire.

## Tasks

### Task A — write the canary test

- **files:** `test/test_admm_knifeedge_canary.jl` (new)
- **action:**
  1. New file, one `@testitem`, named ending in the validation-filter substring
     `(canary, admm)` (mirrors the `(adaptive, rho)` / `(transit, dso)` convention in
     `test_admm_adaptive.jl`), `setup = [Phase8Fixtures]`, `tags = [:admm, :canary]` (`:canary` is
     a new tag — introduced here purely as selectable metadata, matching the existing
     `[:admm, :phase7]`/`[:admm, :reactive]` pattern; it does not exclude the item from the
     default suite, since no such mechanism exists in this repo's `runtests.jl`).
  2. Header comment (above the `@testitem`, `#` lines — no docstring, so
     `format_docstrings = true`'s wrapped-`|` data-loss hazard does not apply): summarize the
     knife-edge finding in 4-6 lines, state explicitly that a bare "did it converge" assertion is
     no longer informative (the production fix converges on every toolchain tested), state the
     `attempts_out`-does-not-reach-the-public-surface finding from Context above verbatim (so a
     future reader doesn't have to re-derive it), and cross-reference
     `.planning/debug/resolved/ieee13-admm-numerical-error.md` by path.
  3. Body: `using TSODSO`; `using Logging: with_logger, SimpleLogger, Warn`. Build
     `kw = Phase8Fixtures.minimal_scenario_kwargs()`, `s = TSODSO.Scenario(; kw..., strategy =
     :admm)`.
  4. Capture ladder-escalation warnings with a plain `Logging.SimpleLogger` (no custom
     `AbstractLogger` subtype — a `struct` definition's legality inside a `@testitem`-generated
     module is unverified in this codebase; `SimpleLogger` needs none). `buf = IOBuffer()`; run
     `r = with_logger(SimpleLogger(buf, Warn)) do ... TSODSO.run_scenario(s) end`; after the call,
     `log_text = String(take!(buf))`; `escalations = count("escalating conditioning", log_text)`
     (`Base.count(needle::AbstractString, haystack::AbstractString)` — non-overlapping substring
     count, no regex needed). This matches the exact tail of `solve_with_retry!`'s `@warn` message
     text in `src/planning/retry.jl`.
  5. Unconditional, loud report FIRST (printed on every run, pass or fail):
     `@info "IEEE-13 ADMM knife-edge canary" iters = r.iters welfare = r.welfare escalations =
     escalations`. This is the "make a future flip attributable" mechanism — a CI log always
     carries the measured numbers.
  6. PINNED assertions (hold across every environment measured to date — native convergence AND
     ladder-rescued convergence alike; a failure here means the trajectory moved, not a flake —
     say so in an inline comment pointing at the resolved debug doc):
     `@test r.iters == 58` and
     `@test isapprox(r.welfare, -4822.903616694139; rtol = 1e-6, atol = 1e-3)` (rtol=1e-6 gives
     ~500x headroom over the ~1.86e-9 max relative spread measured across all 4 recorded
     references — tight enough to flag a genuine trajectory change, loose enough that no
     legitimate toolchain difference observed to date trips it; document this rationale inline).
  7. Deliberately NO assertion on `escalations` itself — whether the ladder fires is a legitimate,
     already-documented environment difference (fires on 1.10/1.11/1.12.5 as measured, not on
     1.12.7's native convergence). State this explicitly in a trailing comment so a future reader
     doesn't "fix" the canary by adding one.
- **verify:**
  - `julia --project=<jf210 scratch env path> -e 'using JuliaFormatter; println(format(["test/test_admm_knifeedge_canary.jl"]; overwrite=false))'` — if `false`, re-run with
    `overwrite=true` and re-check (mirrors the exact recipe used in quick task `260825-eme`).
    Confirm the diff after formatting is only whitespace/style, never content (spot-check the
    known-good welfare digits and the `@warn`-matching string are byte-identical before/after).
  - `julia --project=. -e 'using TSODSO'` still loads cleanly (the new file is not `include`d
    anywhere except via test discovery, so this just confirms no accidental syntax breakage of
    the package itself).
- **done:** `test/test_admm_knifeedge_canary.jl` exists, is JuliaFormatter-clean under the pinned
  2.10.x config, and contains exactly one `@testitem` per the structure above.

## Constraints

- No `src/` changes. The `attempts_out` non-wiring gap identified in Context is documented, not
  fixed — fixing it is a separable task with its own review surface.
- Do not modify `test/test_experiments.jl` or `test/test_admm_adaptive.jl`, and do not weaken any
  existing assertion anywhere in the suite.
- Do not assert on whether the retry ladder fires (`escalations`) — only report it. It is a
  genuine, already-documented environment difference, not a pass/fail signal.
- Task B's throwaway edit and worktree must never touch the real working tree or get committed.
- Format with the pinned JuliaFormatter 2.10.x config only, via the `<scratchpad>/jf210` scratch
  environment; use `overwrite=false` to check before `overwrite=true` to fix (bare `format(path)`

  deletes such text) — moot here since the new file uses no triple-quoted docstrings, but keep in
  mind if the header comment is later converted to one.
