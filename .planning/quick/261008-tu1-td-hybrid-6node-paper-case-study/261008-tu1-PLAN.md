Key framework limitation found during planning: ConvexBranchFlow fixes the feeder root squared
voltage to 1.0, so it cannot natively represent the T&D boundary (v3 = W33 is a decision variable).
No src/ change is allowed. Script-level workaround to TRY FIRST (Task 1): build the DSO block with
`contribute!(ConvexBranchFlow(), ctx, feeder)` on the SAME JuMP model as the SDP block, then
`unfix` the root `v` and `v̂`, re-impose the root's squared-voltage bounds, and add
`v[root] == real(W[3,3])`, `v̂[root] == v[root]`; inject the boundary import (P34, Q34 variables
shared with the SDP node-3 balance) and the fixed loads into the residuals, then `close_balance!`.
If that works and matches the paper-faithful model on the baseline, it is the "framework-hosted"
DSO and unlocks `decompose_dlmp`, `assert_socp_exact!`/`socp_gap_report`, `recover_voltage_angles`
and the exactness copy for experiments 1, 3 and 4. If it fails (internal assumptions, sign
conventions that cannot be reconciled), fall back to a script-local DSO that mirrors the
ConvexBranchFlow conventions and the documented decompose_dlmp formula, and record WHY in the
script header and writeup. Either way the documented finding "ConvexBranchFlow fixes v_root = 1"
goes in the writeup.
