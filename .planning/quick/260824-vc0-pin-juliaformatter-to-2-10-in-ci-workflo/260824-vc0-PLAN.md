# Quick Task 260824-vc0: Pin JuliaFormatter to `~2.10` in the CI format job

## Why

`.github/workflows/CI.yml`'s `format:` job installs JuliaFormatter with
`Pkg.add(PackageSpec(name = "JuliaFormatter", version = "2"))`. In Pkg, a bare `version = "2"` is a
CARET spec (`^2` == `[2.0.0, 3.0.0)`), so it floats. CI run 32791955335 resolved it to
**JuliaFormatter 2.12.6**. `.JuliaFormatter.toml`'s own header comment says the intent was always
"Pinned to JuliaFormatter 2.10.x behaviour" — the workflow just never expressed that intent as a
version constraint. Under 2.12.6, `format(["src","ext","test","docs"])` returns `false`: 48 files
differ, all cosmetic (function-signature/call wrapping near `margin = 92`, docstring reflow,
`r_pct=3.0` -> `r_pct = 3.0` spacing in generated data). There is no code defect — the fix is purely
in the CI workflow's version constraint.

**Locked decision:** pin to `~2.10` (a TILDE spec, `[2.10.0, 2.11.0)`) and touch zero source files.
`version = "2.10"` would NOT fix this — Pkg reads a bare dotted string as a caret spec too
(`^2.10` == `[2.10.0, 3.0.0)`), which still resolves to 2.12.6. Only the tilde prefix pins the
minor version. This must be stated as an explicit in-workflow comment so a future "tidy-up" does
not float it back.

**Explicitly NOT in scope:** any `.jl` file under `src/`, `test/`, `ext/`, `docs/`. No formatting
adoption, no `.JuliaFormatter.toml` change, no other CI job touched.

## Context

- `.github/workflows/CI.yml` — the ONLY file this plan modifies. The `format:` job (currently lines
  49-71) is the target; its `Install JuliaFormatter and check formatting` step runs
  `Pkg.add(PackageSpec(name = "JuliaFormatter", version = "2"))` then
  `format(["src", "ext", "test", "docs"]; verbose = true)` under a `julia --color=yes {0}` shell,
  gated by `if !format(...) ... exit(1) end`. Do not touch the `test:` or `docs:` jobs.
- `.JuliaFormatter.toml` — read-only reference confirming the frozen-style intent ("Pinned to
  JuliaFormatter 2.10.x behaviour"); this plan makes the CI constraint match that documented intent.
  Do not edit this file.

## Tasks

### Task 1 — pin the version spec and document why

- **files:** `.github/workflows/CI.yml`
- **action:**
  1. In the `format:` job's `Install JuliaFormatter and check formatting` step, change
     `Pkg.add(PackageSpec(name = "JuliaFormatter", version = "2"))` to
     `Pkg.add(PackageSpec(name = "JuliaFormatter", version = "~2.10"))`. Use the literal string
     `"~2.10"` — not `"2.10"` (still a floating caret spec under Pkg) and not `"~2.10.0"` (works
     but adds no precision the project needs; keep it at `"~2.10"` to match `.JuliaFormatter.toml`'s
     own "2.10.x" wording).
  2. Immediately above (or beside) that `Pkg.add` line, add a comment explaining: (a) Pkg treats a
     bare version string as a CARET spec, so `"2"` or even `"2.10"` floats to the newest matching
     2.x release and drifted to 2.12.6 in practice, which reformats ~48 files under this repo's
     `.JuliaFormatter.toml`; (b) the leading `~` is a TILDE spec pinning the minor version
     (`[2.10.0, 2.11.0)`), matching `.JuliaFormatter.toml`'s documented "2.10.x behaviour" freeze;
     (c) an explicit instruction not to "simplify" this back to a bare `"2"`/`"2.10"` caret spec.
  3. Do not modify any other line, job, or step in the file. Do not touch `.JuliaFormatter.toml` or
     any `.jl` file.
- **verify:**
  - `git diff --stat .github/workflows/CI.yml` shows exactly one file changed, on the order of a
    handful of added/modified lines (the version string plus the new comment).
  - `git diff .github/workflows/CI.yml` shows no other job (`test:`, `docs:`) touched, and the
    `if !format(...) ... exit(1) end` gate logic unchanged.
  - `grep -n 'JuliaFormatter' .github/workflows/CI.yml` shows `version = "~2.10"` (not `"2"` or
    `"2.10"` without the tilde).
- **done:** the `format:` job's `Pkg.add` line reads `version = "~2.10"`, a comment explains the
  caret-vs-tilde distinction and warns against floating it back, and no other file or job changed.
