# Quick Task 260826-0y4: Fix the vacuous `caught` assertion (soft-scope bug) + record detection method

## Why

A full `Pkg.test()` run on this tree emits exactly ONE Julia soft-scope-ambiguity warning
across the whole suite (30152 passed / 2 known-false Aqua failures / 0 errored / 3 broken —
not in scope):

    Warning: Assignment to `caught` in soft scope is ambiguous because a global variable by the
    same name exists: `caught` will be treated as a new local. Disambiguate by using `local
    caught` ... @ test/test_planning_certification_integer.jl:335

`test/test_planning_certification_integer.jl`'s `@testitem` body runs as **module top-level
code** (TestItemRunner wraps each item in its own module). `caught = nothing` (line 318) is
therefore a module global. The `catch e; caught = e; ...; end` inside the `try` (lines 334-335)
is a **soft scope** relative to that global: Julia treats `caught = e` as a brand-new local that
dies with the `catch` block — the outer `caught` is never touched. The consequence is worse than
a warning: `@test caught === nothing` (line 345) is **VACUOUS**. It passes whether or not
`solve_stackelberg!` throws, because `caught` is permanently the `nothing` assigned at line 318.

This is the SAME bug class already fixed once this session in
`test/test_stochastic_welfare.jl`'s D-06 scan (commit `d8e8999`, the `let`-wrap idiom) — not a
TestItemRunner-specific harness quirk, despite the file's existing "Scoping note (found
2026-08-23 ...)" comment claiming exactly that. That comment got the OTHER half of the fix right
(`result = try ... end` correctly takes the try EXPRESSION's own value — hard-scope rules don't
apply to an expression's return value, only to bare assignments inside the block) but
misdiagnosed the general cause and left the `caught = e` half of the bug unfixed.
