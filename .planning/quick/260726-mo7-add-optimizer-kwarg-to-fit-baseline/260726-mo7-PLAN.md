# Quick Task 260726-mo7: Add `optimizer` kwarg to `fit_baseline`

## Why

Spike 003 (`.planning/spikes/003-phase18-fragility-tolerance/README.md`) proved Phase 18-01's
recorded "population-scale fragility" is a solver-tolerance artifact — but 3 of 5 sweep points
(δ = −0.02, +0.02, +0.05) remain **unmeasurable** because `fit_baseline` always runs at default
solver tolerance and cannot be conditioned. `solve_welfare` already accepts an `optimizer` kwarg
(`src/models/welfare_solve.jl:105`); `fit_baseline` does not.

This unblocks correcting a published v2.1 claim (`sign_flip_survives: false`, shown wrong).

## Scope

Thread a new `optimizer` kwarg to **all three** solver-selection sites inside `fit_baseline`
(`src/pricing/fit.jl:271`):

| # | Line | Site | Note |
|---|---|---|---|
| 1 | 297 | `_fit_opt_solve(...; optimizer = select_optimizer(problem_class(pf)))` | already takes the kwarg |
| 2 | 303 | `Model(select_optimizer(problem_class(pf)))` — FIT AC-PF | |
| 3 | 383-384 | **nested `solve_welfare(relaxed, pf, aggregators; ...)`** for the efficiency ratio | **the one that matters** |

Site 3 is the site whose PF-04 gate (`assert_socp_exact!`) produced the observed
"SOCP relaxation INEXACT — prices REFUSED" errors. The FIT AC-PF (line 357) calls only
`assert_solved!`, never `assert_socp_exact!`. **Threading 1-2 without 3 would fix nothing.**
