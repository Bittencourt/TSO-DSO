## Implementation reference (already reviewed by the planner — reuse directly, no need to re-explore)

- `src/planning/master.jl` — `BendersMaster` (`build_master`, `add_optimality_cut!`,
  `add_feasibility_cut!`, `solve_master!`): leader LP, `y_inv ∈ [0, y_max]`, `z[t]` boxed
  `[0, y_inv]` (`box_lo`/`box_hi`), two epigraphs `α_op ≥ α_op_lb`, `α_x ≥ α_x_lb` (Pitfall M1 finite
  bounds), objective `Min c_y·y_inv + α_op + α_x`. Optimality cuts:
  `α ≥ cost_k + Σ_t grad_k[t]·(z[t]-z_k[t])` for `epigraph ∈ {:op,:x}`. Feasibility cuts:
  `v_k + Σ_t u_k[t]·(z[t]-z_k[t]) ≤ 0` from the follower's genuine Farkas certificate.
- `src/planning/follower.jl` — `FollowerLP` (`build_follower`, `solve_follower!`): `x_inv ∈
  [0, x_inv_max]`, `x_op[t] ≥ 0`, `z[t] in Parameter(0.0)`, `invest_op[t]: x_op[t] ≤ corridor_cap·x_inv`,
  named `coupling[t]: x_op[t] == z[t]` (its dual = `π_s`, or its Farkas ray on infeasibility — no
  penalized-slack shortcut, per CONTEXT.md locked decision). Objective `Min c_inv·x_inv +
  Σ_t c_op[t]·x_op[t]`. Calls `optimize!` directly (never the retry wrapper) so the infeasible branch's
  certificate is never retried away.
- `src/planning/subproblem.jl` — `PlanningOracle` (`build_planning_oracle`,
  `solve_planning_oracle!`): the fixed-`z` operational welfare SOCP (thesis GLB-CVX, eq. 3.31-3.45),
  reusing `contribute!` literally from `solve_welfare`; the pin `p_import[t] = z[t]` is the coupling
  constraint whose dual is the oracle's own gradient `π[t]`.
- `src/planning/benders.jl` — `solve_stackelberg!`: the outer Benders loop (solve master → solve
  follower(`z_k`) → if infeasible add feasibility cut and continue, else solve oracle(`z_k`) → add
  both optimality cuts → track true cost as UB/incumbent → relative-gap stop `≤ 1e-6`).
- `src/planning/coupling.jl` — `SharedTransmission` (`build_shared_transmission`,
  `update_coupling!`, `write_back!`), `DistributorView`: the multi-distributor shared-transmission
  state each distributor's Stackelberg round reads/writes during diagonalization.
- `src/planning/nash.jl` — `NashTrace`, `run_nash!`, `run_nash_probe`: Gauss-Seidel diagonalization
  over distributors to the Nash equilibrium (multi-seed/multi-order probe per NASH-04 — no general
  convergence guarantee, STATE.md concern).
- No binary/integer-expansion machinery exists anywhere in `src/planning/` today — the PSR note's
  problem (8)-(9) binary-expansion + Lagrangian-cut MIP extension is genuinely unimplemented
  (`INT-STRETCH` in STATE.md's Deferred Items table). State this as scope, not silently omit it.
