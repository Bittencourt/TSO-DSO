# Quick Task 260807-bv8: PV-boom HTML report v2 (review-hardened, educational)

## Why

`scripts/pv_boom_report.jl` / `results/pv_boom/report.html` (built by quick task 260807-7nz)
is a good 5-section educational walkthrough, but it will be **independently reviewed by an
external AI (OpenAI Codex)** for accuracy, pedagogy, and craftsmanship. v1 has three gaps a
hostile reviewer will flag: (1) equations carry a thesis-eq-number tag but no exact
source-file/line citation a reviewer can diff notation against; (2) no notation/symbols
glossary — a reader must infer `λ_j`, `l`, `v̂`, `π_s`, etc. from context; (3) no dedicated,
consolidated "here is what is NOT solid" section — the honest findings are scattered across
Sections 2-4 rather than gathered where a reviewer expects them. v1 must NOT be touched
(`scripts/pv_boom_report.jl`, `results/pv_boom/report.html` stay byte-identical) — v2 is a
new, parallel generator.

#### Notation table content (render as an HTML `<table>` — one row per symbol; keep the exact wording of the "meaning" column, it is accurate to the source code cited above)

| Symbol | Meaning | Units / convention |
|---|---|---|
| `p_import[t]` | Active power exchange with the transmission grid (MEM) at the feeder root | pu power; `>0` = buy, `<0` = sell (only when `allow_export=true`) |
| `λ₀[t]` | Wholesale/MEM price at the transmission root (the price `p_import` is settled at) | pu price / pu power |
| `λ_j[t]` (DADP) | Day-ahead dynamic price at bus `j`, hour `t` — the dual of the nodal active-balance constraint `balance_p[j,t]` | pu price / pu power |
| `v[j,t]`, `v̂[j,t]` | Squared voltage magnitude at bus `j` (the SOCP relaxed variable `v`, and `v̂` the LinDistFlow "exactness copy" auxiliary variable that drives the cone to hold with equality) | pu² |
| `l[b,t]` | Squared current magnitude on branch `b` — the loss/current variable in the SOC cone `l·v ≥ P²+Q²` | pu² |
| `P[b,t]`, `Q[b,t]` | Active / reactive power flow on branch `b`, hour `t` | pu |
| `ρ` | ADMM quadratic penalty weight (AGR-OPT / DSO-OPT) | pu⁻¹ (scales a squared-power term) |
| `z[i,t]` | Distributor `i`'s frontier import/export at the shared transmission corridor — the planning-layer coupling variable (`p_import == z`) | pu power |
| `x_inv[i]` | Distributor `i`'s converged flexibility-investment level (planning-layer decision) | pu |
| `π_s` | Dual of the planning-layer coupling constraint `p_import == z`; the Benders cut gradient — a "linking price" conceptually analogous to a DLMP (per README's own language) | pu price / pu power |
| `pv_mult` | PV-penetration multiplier scaling per-bus PV magnitude — a parameter of THIS case study only (`pv_boom_case_study.jl`), not a framework-wide symbol | dimensionless |

#### Honest-limitations section content (five items — do not add, remove, or soften any)

1. **Welfare-level meaninglessness** — every device utility has its additive thesis
   constant `c` deliberately dropped (RESEARCH A5, stated in every device docstring); only
   welfare DELTAS between scenarios and DUALS (prices) are economically meaningful, never
   the reported level in isolation (already in v1's `.finding` box, Section 2.2).
2. **EXACT-04 SOC inexactness under high-PV reverse flow** — the certified 3-bus stress
   fixture (`pv_scale=1.2`, `load_scale=0.2`, `vmax=1.05`) shows the SOC relaxation
   genuinely INEXACT at 10/24 hours (`obj_gap=8.700808e-01`,
   `socp_maxgap=1.043774e+01` under the documented `rtol_exact=1.0` diagnostic override) —
   the IEEE-13 sweep itself never exhibits this (all 6 `pv_mult` points stay exact to
   O(1e-8)-O(1e-9)).
3. **The `pv_mult>=0.7` Benders feasibility floor deviation** — `solve_stackelberg!`'s
   Benders master's unconditional first trial is `z=0`; a zero-PV network cannot
   self-balance zero frontier import, so `pv_mult ∈ {0.0, 0.3, 0.5}` all raise a hard
   `INFEASIBLE` before any cut is attempted; `pv_mult >= 0.7` is the feasibility floor.
   `pv_mult=0.7` was substituted for the intended `0.0` baseline.
4. **Nash non-differentiation** — the converged planning game gives
   `x_inv = [0.0, 0.0]` for both distributors at this calibration: a genuine, reported-as-is
   finding, never forced apart.
5. **"Directional, public-data" thesis-reproduction qualifier** — quote `README.md`'s own
   language (lines 77-81): "the thesis's DSO-surplus sign flip reproduces on real public
   data; the +25% welfare-ratio magnitude does not — stated plainly, always with the
   'directional, public-data' qualifier, pinned only on sign-safe quantities." State this is
   a repo-wide reproduction-honesty convention, not something specific to the PV-boom study.
