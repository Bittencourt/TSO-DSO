# Quick Task 260822-f0b: Three small seams so the IEEE-8500 headline fixture can be run end-to-end

## Why

`25-VERIFICATION.md` (2026-08-22) scored Phase 25 7/9, with the two failures both rooted in the same
family of small, controllable gaps rather than the (already-accepted) OOM memory wall:

- The sweep's ONE completed row on the true headline fixture (`ieee8500`, T=10, density=0.1) came back
  `ALMOST_OPTIMAL`, not `OPTIMAL` — because the sweep solved it at `tol_gap=1e-8`, a tolerance the
  committed ladder (`results/ieee8500_benchmark/noise_floor_calibration.csv`) already measured to
  **fail** on both IEEE-8500 fixtures (`ieee8500` floor is `1e-7`; `1e-8` gives `NaN`). Item 1 below
  fixes this.
- `deferred-items.md` item 3 (still open): `solve_admm`'s hardcoded final-consolidation
  `assert_socp_exact!` call has no override seam, so a genuinely converged ADMM point on either
  IEEE-8500 fixture throws at the `~1e-3`-scale measured noise floor against the project's `1e-6`
  default. Item 3 below adds the seam (does NOT change any default or weaken the gate — additive
  only, per the standing anti-certificate-laundering bar, T-25-12).
- The headline T=10 point hit `budget_exceeded` after only 6 ADMM iterations at the harness's
  120s cap — far too short to observe convergence at ~20s/iteration. Item 4 below raises the
  default.

None of these three changes touches the OOM/memory wall (`25-VERIFICATION.md` human-verification
item 1, deferred-items.md item 4's memory component — already partially resolved by the `--t-horizon`
flag in gap-closure task 25-08) or the SCS-crossover gap (`25-VERIFICATION.md` human-verification
item 2) — those remain separate, out of scope here. This task only removes the tolerance/budget
seams that block a genuinely converged, honestly-classified headline run once the researcher decides
to attempt one.
