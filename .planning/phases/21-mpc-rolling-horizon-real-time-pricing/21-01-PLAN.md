<objective>
Widen the three stateful device files (`PVBattery`, `Thermostatic`, `FourQuadBESS`) and the
`Aggregator` roll-up so every per-step-varying quantity a future receding-horizon window must
slide without rebuilding — initial-condition states (`soc0`, `Tin0`), PV availability (`Ppv`),
ambient temperature (`Tout`), and inelastic demand (`Pdc`) — is backed by a genuine JuMP
`Parameter` instead of a literal `Float64` baked in at `contribute!` time.

Purpose: RESEARCH.md's Pitfall 1 is the central blocker for the whole phase: today
`PVBattery.jl:253`/`Thermostatic.jl:237`/`FourQuadBESS.jl:300` bake `soc[1]==d.soc0`/
`Tin[1]==d.Tin0` as an anonymous, unregistered, immediately-discarded `@constraint`, with no
handle to re-target it without rebuilding — directly violating MPC-01's "built once and
re-solved per step, never rebuilt" acceptance criterion and CLAUDE.md's hard build-once rule.
This plan makes the SEAM-01 `horizon_state` stub (`src/models/oracle.jl:76-80`) concretely
implementable in Wave 2. It also widens `Aggregator.Pdc` beyond RESEARCH.md's literal
Ppv/Tout-only sketch: D-08 explicitly requires perturbing "PV **and demand** ground truth", and
`Aggregator.Pdc` — not `Thermostatic.Tout` — is this project's actual inelastic-demand
quantity, so omitting it would silently under-deliver D-08.

Every change is additive and defaults to the SAME literal value the device/aggregator held
before (`Parameter(d.soc0)` defaults to `d.soc0`, etc.) — no existing caller that never calls
`set_parameter_value` observes any behavior change (the byte-identical-default invariant every
prior MESH-04/OVR widening in this codebase upholds, e.g. `q_inject`'s optional-field precedent).

Output: four modified `src/devices/*.jl` files with widened `contribute!` return tuples, plus
new regression `@testitem`s in the four corresponding `test/test_*.jl` files proving both the
Parameter mechanics and the byte-identical default.
</objective>
