<objective>
Implement REACT-01's actual code change: promote the ADMM `DSO-OPT`'s per-load-node reactive
draw from a `Float64` constant to a genuine, pinned JuMP coupling variable `qag_dso[j,t]`
(mirroring the existing `pag_dso`/`:balance_p` block in the SAME file), gated behind a
`reactive_consensus::Bool = false` kwarg whose default preserves today's behavior byte-for-byte
(REACT-03's non-regression discipline). Add the `assert_no_slack` certificate on `:balance_q`
so its dual becomes trustworthy/publishable, mirroring the existing `:balance_p` certificate.

Purpose: today `:balance_q` is ALREADY a genuine equality in both the centralized and ADMM
solves (verified by 16-RESEARCH.md's direct code read — no change needed there), but its ADMM
dual is only as trustworthy as the lenient `strict=false` final solve it comes from, and the
per-load-node injection feeding it is a hand-summed constant rather than a first-class decision
variable. This plan makes the mechanism structurally identical to the already-trusted active
DADP path, without building the (explicitly unnecessary, per Assumption A1) live μ dual-ascent
machinery: `qag_dso` is PINNED to the fixed target `q_draw[j][t]` via an explicit equality
(`AgrOpt.qag` never moves — thesis A3, no reactive DER decision exists to iterate on), so there
is no ρ-penalty, no dual-ascent, and no new residual trace needed for it.
Output: `build_dso_opt`/`solve_admm` gain the `reactive_consensus` kwarg; the RED items in
`test/test_admm_reactive.jl` (Plan 16-01) that guard on this kwarg now report GREEN.
</objective>
