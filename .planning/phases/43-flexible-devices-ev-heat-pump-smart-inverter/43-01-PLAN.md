**Design decisions (locked for the executor):**

1. `has_reactive_decision(d::AbstractDevice)::Bool` — default `= is_flexible_load(d)`, defined
   on the abstract type in AbstractDevice.jl right after `is_flexible_load`. This default IS the
   old probe's flexible-load half, made explicit. Typed override
   `has_reactive_decision(::FourQuadBESS) = true` goes in the NEW file
   `src/devices/CapabilityTraits.jl` (included after FixedCapacitor.jl, before Aggregator.jl) —
   NOT in FourQuadBESS.jl (byte-identical golden files are not touched: research Pitfall 6
   warning list Thermostatic/PVBattery/Scenario; we extend the same discipline to all existing
   device files). Resolution on existing devices: FourQuadBESS → true (override);
   Thermostatic/Deferrable/Interruptible → true (via is_flexible_load default);
   PVBattery and FixedCapacitor → false (is_flexible_load default false) — the A8 asymmetry
   reproduced by construction, asserted by test.
2. `storage_kind(d::AbstractDevice)::Symbol` — default `:none`; values `:battery` (PVBattery),
   `:four_quadrant` (FourQuadBESS), `:ev` (reserved, added by 43-02). Overrides for existing
   devices live in CapabilityTraits.jl for the same golden-untouched reason.
3. Device-type provenance for the stash (research A4): ModelContext gains
   `agg_device_types::Dict{Int, Vector{DataType}}` (constructor: empty dict; docstring line
   beside agg_device_vars). Aggregator.jl appends `typeof(d)` in lockstep with the vars append
   (same loop iteration, same bus key) — one line, behaviorally inert (nothing reads it on any
   existing path's outcome).
4. Certificate selection rule in welfare_solve.jl: a stashed vars entry is battery-checked iff
   its PAIRED type (same bus, same index — both appended by the same loop) has
   `storage_kind === :battery`; if the type list is absent or shorter than the vars list
   (hand-built test contexts like test_welfare_solve.jl's synthetic `ctx.agg_device_vars`
   entries), FALL BACK to the legacy shape predicate
   `haskey(v,:p_ch) && haskey(v,:p_dch) && !haskey(v,:q)` and keep a comment saying why
   (existing hand-built certificate tests stay green; production paths always pair).
   Same pairing rule for `_react_outputs` in admm_state.jl: select entries whose paired type has
   `storage_kind === :four_quadrant`, same legacy fallback
   (`haskey(v,:p_ch) && haskey(v,:p_dch) && haskey(v,:q)`). complementarity_4q.jl itself is NOT
   touched (its own selection can never false-match an EV — no :q key — and its measured
   tolerance file is golden-sensitive).
5. DsoOpt.jl: `_any_flexible_reactive`'s inner predicate becomes
   `any(has_reactive_decision, agg.devices)`; the inline copy in the :326 guard is replaced by a
   call to a tiny per-aggregator helper (`_agg_has_reactive_decision(agg)`) that
   `_any_flexible_reactive` also uses — ONE predicate, three consumers (kwarg default, guard,
   `_default_reactive_consensus` which needs no textual edit because it delegates). Error
   message text in the guard is updated to name the trait instead of the isa-test; the
   `normalize_reactive_mode` discipline is untouched.
