<objective>
Close the FIX-05 defect for the two ALREADY-aggregatable flexible-load devices: `Thermostatic` and
`Deferrable` currently return `(; vars, p_inject, utility)` with NO reactive term at all — the
Aggregator applies `tanφ` only to the inelastic `Pdc` term, never to a flexible load's own
consumption. Add an `is_flexible_load` trait, an optional per-device `φ` override, and wire the
Aggregator's roll-up to sum `p_inject[t] * tan(arccos φ_used)` into `q_inject` for any flexible-load
member. (`Interruptible`'s Variant-1 -> Variant-2 conversion, which this trait also targets, is a
separate concern with a larger, non-Aggregator-file blast radius — handled by Plan 26-07, which
depends on this plan.)

Purpose: thesis eq. 3.23's power-factor reactive draw must apply to EVERY flexible load's
consumption, not just the fixed inelastic demand.
Output: `is_flexible_load` trait (default `false`, `true` for `Thermostatic`/`Deferrable`);
Aggregator roll-up extension; optional `φ` override on both devices; a per-device `:Rq == p*tanφ`
test for each.
</objective>

EXACT shape to extend:

```julia
p_inject = AffExpr[zero(AffExpr) for _ in 1:T]
q_inject = AffExpr[zero(AffExpr) for _ in 1:T]
utility = zero(QuadExpr)
device_vars = Any[]
for d in agg.devices
    res = contribute!(d, ctx; T = T)
    for t in 1:T
        p_inject[t] += res.p_inject[t]
    end
    if hasproperty(res, :q_inject)
        for t in 1:T
            q_inject[t] += res.q_inject[t]
        end
    end
    utility += res.utility
    push!(device_vars, res.vars)
end
```
