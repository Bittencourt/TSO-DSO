<objective>
Convert `Interruptible` from the self-injecting Variant-1 device contract to the aggregatable
Variant-2 contract (per `AbstractDevice.jl`'s own documented "TWO variants" and the CONTEXT.md
decision that the Aggregator remains the SOLE `:Rp`/`:Rq` writer), so it can draw power-factor
reactive power through the SAME `Aggregator` roll-up Plan 26-04 wired for `Thermostatic`/
`Deferrable`. `Interruptible` is the ONLY live Variant-1 device in the codebase — converting it
makes `src/models/linear_solve.jl`'s device loop (which today assumes Variant-1 self-injection,
confirmed by direct code read: `ctx.meta[:device_vars] = [contribute!(d, ctx; T=T) for d in
devices]` with NO residual/objective write of its own) structurally obsolete unless it is updated
in the SAME plan — this is NOT optional test-only cleanup, `solve_linear` is production code with
its own live callers (`test/test_conformance.jl`'s DC<->LinDistFlow crit-4 item calls it directly
with a raw `Interruptible`, not wrapped in an Aggregator).

Purpose: give `Interruptible` the same FIX-05 reactive-draw path as `Thermostatic`/`Deferrable`
without leaving `solve_linear.jl` silently broken (a converted device that stops writing its own
injection would manufacture free welfare or vanish from the balance — the exact CR-01 failure mode
`solve_linear.jl`'s own comments warn about).
Output: `Interruptible.contribute!` returns `(; vars, p_inject, utility)`; `linear_solve.jl`'s
device loop performs the residual/objective write generically for ANY Variant-2 device; the 3 live
call sites (`test/test_device.jl`, `test/test_linear_solve.jl`, `test/test_conformance.jl`) are
updated to the new contract (`test/test_planning_oracle.jl` needs NO change — confirmed by grep, it
only mentions `Interruptible` in a comment, never calls `contribute!` on one).

Depends on Plan 26-04 (both touch `src/devices/AbstractDevice.jl`'s `is_flexible_load` trait
region, and this plan's new test needs `Aggregator`'s flexible-load roll-up, which 26-04 adds).
</objective>

function contribute!(d::Interruptible, ctx::ModelContext; T::Int = 1)
    m = ctx.model
    p = @variable(m, [t = 1:T], lower_bound = d.Pmin, upper_bound = d.Pmax)
