Boundary guards: `isempty(aggregators) && throw(ArgumentError(...))`;
`length(λ₀) == T || throw(ArgumentError(...))`; per-aggregator bus-range check
`1 <= agg.bus <= Np || throw(ArgumentError(...))`.

Bridges registered on every model before any solve (mirrors verbatim):

Frontier construction: `allow_export ? @variable(model, p_import[t=1:T]) :
@variable(model, p_import[t=1:T] >= 0)`; `reactive = haskey(ctx.residuals, :Rq)` captured
RIGHT AFTER `contribute!(pf, ctx, feeder; T)` and BEFORE any aggregator write.

Residual closure + registration (the NAMED-macro form `@constraint(model, balance_p[...], ...)`
is safe ONLY because `solve_welfare` calls it exactly once per model — this plan's S-scenario
loop MUST instead use the ANONYMOUS array-constraint form `@constraint(model, [j=1:Np,t=1:T],
...)` with no name, to avoid the SAME `"An object of name balance_p is already attached"`
collision `ConvexBranchFlow.contribute!` has for its OWN named containers — see the
`JuMP.unregister` workaround below, which solves the pf-formulation half of this problem; the
balance constraints need the orthogonal ANONYMOUS-construction fix instead, since
`register_constraint!(ctx, :balance_p, cref)` stores the handle in `ctx.constraints` (a
per-`ModelContext`-instance `Dict`), NOT in the `Model`'s object dictionary, so S independent
`ModelContext`s can each safely register their own `:balance_p` key with zero collision.

Objective: `welfare = ctx.meta[:objective] - sum(λ₀[t] * p_import[t] for t in 1:T);
@objective(model, Max, welfare)`.

Solve + gate ordering (STRICT — never violate): `assert_solved!(model; dual=true,
allow_local=allow_local)` FIRST, THEN (gated on `haskey(ctx.meta[:pf_vars], :l)`)
`assert_socp_exact!(ctx; rtol=rtol_exact)`, THEN `assert_battery_complementarity!(ctx; τ=τ,
T=T)`, and ONLY THEN any `dual()` read.

From src/powerflow/ConvexBranchFlow.jl — the ONE genuinely new mechanical fact this phase
introduces (verified live, RESEARCH.md Pattern 1): calling `contribute!(::ConvexBranchFlow,
ctx_s, feeder; T)` a SECOND time on the SAME `Model` throws `"An object of name v is already
attached to this model"` unless `JuMP.unregister(model, name)` is called for EVERY one of
these nine names between scenario blocks: `:v, :v̂, :P, :Q, :l, :cone, :vdrop, :cpydrop,
:smax`. `JuMP.unregister` frees only the NAME (object-dictionary lookup), not the underlying
`VariableRef`/`ConstraintRef` objects already captured in `ctx_s.meta[:pf_vars]`/
`ctx_s.constraints` — those remain independently usable after the NEXT scenario's
`contribute!` call. Never call `unregister` after the LAST scenario (nothing follows it).

From src/devices/PVBattery.jl — `contribute!(d::PVBattery, ctx; T)` returns

`p_dch`/`soc` are `Vector{VariableRef}` of length `T` — the handles this plan's

From src/devices/Aggregator.jl — `contribute!(agg::Aggregator, ctx; T)` is the SOLE `:Rp`/

nonanticipativity walk finds each scenario's battery vars (`haskey(v, :soc0)` marks a
