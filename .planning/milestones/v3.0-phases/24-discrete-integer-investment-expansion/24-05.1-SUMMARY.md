# Phase 24 Plan 05.1: Gap-Closure — Fix the Certified LL-Cut Defect (Three Stacked Bugs) Summary

**Fixed the LL-cut Q_nu recourse-value defect plan 24-05's certification found, then
discovered and fixed two further independent defects (an over-eager no-good stall
heuristic, and a too-loose HiGHS MILP feasibility tolerance) that the Q_nu fix alone
did not resolve — the certified integer Benders loop now converges cleanly to machine
precision, with zero no-good cuts, in 9 iterations.**

## Performance

- **Duration:** ~3h wall clock (includes root-cause investigation via direct-execution
  diagnostics, not just the code changes)
- **Completed:** 2026-08-23
- **Tasks:** 4 commits (3 `fix`, 1 `test`)
- **Files modified:** 4

## Accomplishments

- **Fix 1 — the stated defect (`ll_cut_recourse`/`corner_recourse`,
  `src/planning/benders.jl`):** `apply_integer_cuts!` is now handed the TRUE
  per-corner minimized recourse `Q(y_inv(b^ν)) = min_{z∈[0,y_inv]}[follower_cost(z) -
  oracle_welfare(z)]`, computed via the SAME ternary-search technique
  `test_planning_certification_integer.jl`'s own `enumerate_lattice` reference
  implementation uses, reusing the REAL, already-built `oracle`/`follower`.
  `ll_cut_recourse` dispatches to a TRUE no-op for the continuous `BendersMaster`
  (returns its input unchanged, touches zero state) — the continuous path is
  byte-identical. Also captures `oracle_status_k` immediately after the oracle's own
  solve at `lb_res.z`, before `corner_recourse`'s internal ternary search re-solves
  oracle/follower at other trial points, so the trace's `oracle_status` field is not
  contaminated.
- **Fix 2 — a second, independently-discovered defect (`apply_integer_cuts!`,
  `src/planning/master_integer.jl`):** the anti-stall no-good heuristic banned ANY
  revisited corner on its second visit, regardless of whether the master's own `z`
  trial was still genuinely converging. Empirically confirmed (before this fix) that
  the master's `z` at the TRUE optimal corner moved `0.195 → 0.442 → 0.497 → 0.500`
  (real, converging progress) while being banned after the 2nd of those visits, at
  `UB=-0.194`, still `~0.03` short of the true minimum `-0.225` — making the
  certified UB-match assertion provably unreachable regardless of `Q_nu` correctness.
  `master.visited` is now `Dict{Vector{Int},Vector{Float64}}` mapping each corner to
  its last `z` trial; a genuine stall requires the SAME corner AND an UNCHANGED `z`
  (within the new `STALL_Z_ATOL = 1e-6`).
- **Fix 3 — a third, independently-discovered defect
  (`select_optimizer(::MILP)`, `src/solver/factory.jl`):** with fixes 1+2 applied, the
  certified run still missed the exact-match test by a small, fully DETERMINISTIC
  (bit-for-bit reproducible across repeated runs) `~7e-8` residual — above
  `KNOWN_OPTIMUM_ATOL` (`~4e-8`). Root-caused to HiGHS's runtime default
  `mip_feasibility_tolerance` (`1e-6`) accepting a `z` up to `~1e-6` outside the
  master's own box bound `z <= y_inv` as "feasible"; at this fixture's true-optimal
  corner, whose argmin sits exactly on that boundary, this slack translated via the
  recourse function's local slope into the observed residual — and could never shrink
  with more Benders iterations, since the master had already reached a genuine
  numerically-limited fixed point. Tightened to `1e-9` (empirically verified: `1e-7`
  and `1e-8` also suffice) — closes the residual to `~1.6e-16` (machine precision).
- **Test update (`test/test_planning_certification_integer.jl`):** both `@test_broken`
  markers (per-cut LL validity; `result.UB ≈ enum_result.best_total`) converted to
  genuine `@test`s — required by Julia's own `@test_broken` semantics (an
  unexpectedly-passing `@test_broken` fails the suite). The `try`/`catch` gate
  assertions were rewritten (`caught === nothing` replaces the old "fails loudly"
  checks, since the loop no longer throws), and D-16/`converged_via` assertions were
  strengthened to assert the STRONGEST form ("`:clean`, zero no-good cuts", not merely
  "`m > 0` is tolerated") since that is what this fixture now genuinely achieves. File
  header and inline comments rewritten to document all three defects and the fix.

## Root-Cause Investigation (why three fixes, not one)

The task brief anticipated ONE defect (the `Q_nu` recourse value). Verifying that fix
in isolation, via direct-execution scripts mirroring the certification `@testitem`
(the sanctioned workaround for the TestItemRunner sibling-worktree hazard,
`MEMORY.md`), confirmed it resolved D-15 certificate 1 perfectly (0 cut-validity
violations, reproducibly, across every LL cut fired in a full 50-iteration run) but
left certificate 2 (`result.UB ≈ enum_result.best_total`) failing with the master
MILP eventually reaching genuine infeasibility — a DIFFERENT failure mode than the
original defect's, tracing to `apply_integer_cuts!`'s own stall-ban logic excluding
the true-optimal corner before its incumbent converged. Fixing that second defect
made the run converge (no more infeasibility), but landed on a stable, deterministic
`~1.7×` overshoot of `KNOWN_OPTIMUM_ATOL`. Because the overshoot was bit-for-bit
reproducible (never flaky) and the LL-cut algebra/`L`/`KNOWN_OPTIMUM_ATOL` were all
independently re-confirmed unaffected and correct, the investigation traced it to the
master MILP's own solver-tolerance-limited box-constraint precision — resolved by
Fix 3. Each fix was verified in isolation (via direct-execution scripts, not just
inference) before moving to the next, and the final state was re-verified end-to-end
multiple times for determinism before committing.
