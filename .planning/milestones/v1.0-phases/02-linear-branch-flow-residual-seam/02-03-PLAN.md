## Phase Goal

**As a** power-systems researcher, **I want to** express a linear distribution-network formulation and a flexible load that meet only at a shared nodal residual and solve them centrally, **so that** I obtain the first nodal-balance dual (the distribution price) and can swap DC↔LinDistFlow without touching device or assembly code.

<objective>
Introduce the project's first *device* contract (`AbstractDevice` + a dispatched `contribute!`) and its first concrete member, the interruptible/elastic load (DEV-03). The device creates its own decision variable with power bounds, *adds* a signed power injection into the shared `:Rp` residual, and *adds* a concave quadratic utility `a·p − (b/2)p²` into the QuadExpr objective accumulator — and it is passed only its bus id and horizon `T`, never the feeder. That decoupling (device ⟂ network) is exactly what success criterion 2 tests.

Purpose: establish that devices meet the network only at the residual seam, with utility flowing to the separate objective accumulator (not the affine residual). This contract is reused by the full device library in Phase 3.
Output: `AbstractDevice.jl`, `Interruptible.jl`, and `test/test_device.jl`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| researcher-supplied utility coefficients (a,b) → welfare objective | b ≤ 0 makes utility convex → maximization unbounded/non-convex → garbage or solver failure |
| device injection sign → nodal balance | A flipped injection sign flips the recovered price (cost looks like a credit) while staying feasible |
| device ↔ network | The device must not see the feeder; a leaked topology reference silently couples layers and defeats swappability |
