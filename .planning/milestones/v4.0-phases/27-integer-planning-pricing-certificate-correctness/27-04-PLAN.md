mathematically are per FIX-07: `cone` (the rotated-SOC cone-slot multiplier, thesis 3.39,
currently misleadingly named `loss`) and `drop` (the voltage-drop/copy-drop multiplier, thesis
3.33/3.43, currently named `voltage`). Keep `.loss`/`.voltage` working as ONE-TIME

"voltage component ≈ 0 when unbinding" test property with the correct one: a component is zero

fixture.

file's own header (`cone_dual_b[3]` and `dual(:vdrop)+dual(:cpydrop)` respectively) — calling

(PM-01: the exactness-copy default is a restriction, not a genuine relaxation) means "voltage
bound not binding" and "drop-multiplier is zero" are no longer the same physical statement, so
the old test's magnitude-based claim is not just mislabeled but factually incorrect post-Phase-26.
Output: renamed, correctly-derived component fields; a working, warning deprecation alias; a
corrected multiplier-zero-iff test on a realistic fixture; the sum-to-price identity preserved
exactly.
