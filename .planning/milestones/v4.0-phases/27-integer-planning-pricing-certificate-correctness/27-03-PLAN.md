<objective>
Settle `run_mpc`'s (src/experiments/mpc_loop.jl) realized welfare and regret against the TRUE
plant, per FIX-10 (as amended by the post-research CONTEXT decision): realized PV clips battery
charging to the TRUE (unperturbed) availability, true-state propagation THROWS on a genuine SOC
bound violation, and the true import is LOSS-EXACT — a per-applied-hour power-flow re-solve with
every device's realized (clipped) net injection fixed and only the frontier import free — never
the copper-plate net-injection approximation. The pre-existing forecast-consistent number is
kept, renamed `forecast_settled_welfare`, as a clearly labelled diagnostic; `regret` is
re-derived against the new truth-settled `realized_welfare`.

Purpose: `realized_welfare`'s own docstring already documents its forecast-consistent
convention as an approximation — under nonzero `mpc_forecast_error`, the applied `p_ch` can
exceed the TRUE PV availability (Assumption A6 violated on the ground truth) and the frontier
import balances a forecast-perturbed network, not the real one. This phase closes that
documented gap so the headline realized-welfare/regret numbers reflect what a real plant would
actually deliver, not what the optimizer merely believed.
Output: `run_mpc` truth-settled; the zero-forecast-error byte-identity invariant preserved as a
regression; a forced-PV-shortfall fixture proving the clip/loss-exact-import/throw behavior.
</objective>
