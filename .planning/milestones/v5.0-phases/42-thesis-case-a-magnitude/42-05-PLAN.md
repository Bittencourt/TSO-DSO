## Runtime discipline (binding for every task in this plan)

- **ONE measurement process at a time.** A full-scale solve observes ~4 GB; the box has ~4 GB
  available. NEVER run two `julia scripts/case_a_magnitude.jl` invocations concurrently, and do
  not run them alongside a test suite.
- **Every heavy invocation is a background shell** (`background: true`) with a generous timeout
  (per-seed headline: 5400000 ms = 90 min ≥ the 25–40 min estimate ×2; cross-check/lenses:
  7200000 ms; per-axis ablation: 5400000 ms). Monitor via output files / `magnitude.csv` row
  growth — do not poll-spin.
- **Kill-anytime:** if an invocation stalls past its budget, kill it; the upsert contract keeps
  every captured row; re-invoke to resume (upsert keys supersede in place). A kill is a measured
  outcome, not a failure to hide.
- **Honesty policy:** a refusal (`error:CertificateError` at the default rung — the EXPECTED
  first outcome, twice committed in prior phases), a FIT failure, a `:budget_exceeded`, or a
  ladder exhaustion are ALL valid completions of a task. What is NOT valid: loosening a gate,
  touching ρ/τ, re-tuning, or dropping a row. If the certified rung exhausts the ladder
  (`error:ladder_exhausted`), record it, commit it, and continue to the next seed/axis — the
  phase succeeds on the honesty of the measurement (PROJECT.md v5.0).
- **Commit after each unit** (per seed, per axis): the CSVs' git history is the no-cherry-picking
  audit trail.
</execution_notes>
