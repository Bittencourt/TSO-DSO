<sign_convention>
## The oracle's optimality-cut sign convention (derive once here, reused in plan 11-02)

`solve_planning_oracle!` returns `cost` as a MAX-sense welfare value and `π` as the dual of the
pin constraint. Phase 10 D-06 already empirically established (10-RESEARCH.md Pitfall 1,
`test_planning_oracle.jl`'s dual-sign regression) that `π` is monotonically NON-DECREASING in
`z`, i.e. `π = -∂welfare/∂z` — `π` is ALREADY the correctly-signed gradient of the CONVEX function
`g(z) = -welfare(z)`. Therefore, when plan 11-02's `benders.jl` forms the oracle's optimality cut
on the master's `α_op` epigraph, it must use `cost_k = -oracle_res.cost` (negate the returned
welfare into a genuine cost) paired with `grad_k = oracle_res.π` (used AS-IS, no further negation
— Phase 10 already did the sign work). This plan's `add_optimality_cut!` is sign-agnostic (it
takes whatever `cost_k`/`grad_k` the caller supplies); this note exists so plan 11-02 does not
have to re-derive it.

The FOLLOWER's own coupling-dual sign is NOT pre-derivable this way (JuMP's dual-sign convention
for an equality constraint in a Min-sense LP is not independently re-derived here) — Task 1 below
measures it empirically on the toy fixture and pins whichever sign is OBSERVED as a permanent
regression, mirroring Phase 10 Pitfall 1's own "measure, don't guess" methodology.
</sign_convention>
