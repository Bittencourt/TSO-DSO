<objective>
Deliver the two resilience primitives PLAN-03 needs before any Benders code exists: a bounded,
escalating-retry wrapper around the project's sole solve choke point (`assert_solved!`) that
survives the documented intermittent Clarabel `NUMERICAL_ERROR` without ever silently trusting a
bad result or falling back to a lower-accuracy solver, and a per-iteration checkpoint save/resume
primitive that never treats a possibly-partial checkpoint as complete.

future Benders loop; STATE.md's carried blocker says this amplifies the known Clarabel
conditioning flake. Both primitives must exist and be independently proven BEFORE plan 10-02
wires them into `solve_planning_oracle!`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-process trial solve -> retried result | A caught `NUMERICAL_ERROR`/`SLOW_PROGRESS` must never silently surface a stale or partially-converged price if the retry budget is exhausted |
| local filesystem <-> checkpoint file | Checkpoint files live under a local, gitignored directory (no network, no external/untrusted input); the risk is a partially-written file being read back as "complete" after a crash mid-write |

This is a single-process, in-process Julia numerical-optimization library with no network
input, authentication, or session boundary — web/injection/auth threats are explicitly out of
scope (per project security note). The threats below are the genuine ones: research-provenance
integrity and never silently corrupting a run.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | `solve_with_retry!` budget exhaustion | mitigate | D-10: on exhaustion, raise loudly with full status diagnostics (`termination_status`/`primal_status`/`dual_status`/`raw_status`) and the exhausted attempt count — never a silent fallback value |
| T-10-02 | Tampering / Repudiation | `checkpoint_iteration!`/`resume_from_checkpoint` | mitigate | `resume_from_checkpoint` always treats the highest-numbered file as "redo, never trust-complete" (D-10); `@tagsave(...; safe = true)` never silently overwrites a prior checkpoint |
| T-10-03 | Denial of Service | retry ladder | mitigate | Bounded `max_attempts` (default 4); non-retryable statuses (`INFEASIBLE`, `DUAL_INFEASIBLE`, `INFEASIBLE_OR_UNBOUNDED`) re-raise immediately on attempt 1, never burning budget on a genuine modeling failure |
| T-10-04 | Tampering | solver-accuracy substitution | mitigate | No SCS fallback on `NUMERICAL_ERROR` (D-09/CLAUDE.md) — only Clarabel conditioning attributes are escalated, so a retried solve's duals stay IPM-grade |
| T-10-SC | Tampering | npm/pip/cargo-equivalent (Julia Pkg) installs | accept | Zero new packages this plan (`Project.toml`/`Manifest.toml` unchanged) — DrWatson/JLD2 are already-resolved dependencies (10-RESEARCH.md Package Legitimacy Audit: not applicable) |
</threat_model>
