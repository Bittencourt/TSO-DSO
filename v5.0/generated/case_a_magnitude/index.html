Case A Welfare-Gain Magnitude — the honest, pre-registered measurement

This page is the writeup of the Phase 42 Case A welfare-gain magnitude measurement: the DADP-vs-FIT welfare gain of the real 784-house Case A population, measured under a PRE-REGISTERED protocol (42-CASE-A-PROTOCOL.md in the phase's planning directory, committed BEFORE any Case A run executed) and reported AT WHATEVER MAGNITUDE IT MEASURED — the PROJECT.md v5.0 honesty policy. It is the evidence chain's last link:

  • REPRO-03 — the SIGN-SAFE welfare-gain definition, pre-registered and guarded;
  • REPRO-04 — the headline measurement at the frozen registered configuration: five master seeds, the bounded AGR solver-precision ladder, the centralized cross-check, and the four-leg settlement lenses;
  • REPRO-05 — the four-axis OFAT ablation (FIT parameters, price range, population, device mix) and the written gap-attribution statement.

Page contract. This page READS results/thesis_case_a_magnitude/*.csv exactly as committed by scripts/case_a_magnitude.jl and SOLVES NOTHING — its whole live slice is reading those CSVs and recomputing the derived figures from the rows (seconds; the docs build's 30-minute CI budget is safe). Every relative figure below is RECOMPUTED LIVE from the committed rows (the Phase-28 CR-01 discipline: no stale derived number can survive a data revision), every division is SIGN-SAFE (denominator abs(W_FIT)), and every magnitude number is printed through ONE qualifier helper (defined below).

The locked statements (protocol §1–§2, §9–§10)

The registered relative gain is Δ% = 100·(W_DADP − W_FIT)/|W_FIT| — SIGN-SAFE. The naive ratio W_DADP/W_FIT is NEVER reported anywhere in this project: welfare is large and NEGATIVE at the 784-house population, so the ratio sign-inverts (a positive-looking number for a welfare LOSS). The SOC-exactness gate, the battery τ and ρ = ADMM().ρ were never loosened or re-tuned — refusals and infeasibilities are recorded MEASURED outcomes, answered only by the pre-registered ladder and its ONE sanctioned solver-tightened retry. "Gap not fully attributed" and "whatever the magnitude" are acceptable, pre-registered endings: closing the gap to the thesis's +25% was NEVER a success condition.

using TSODSO

function read_case_a_csv(path)
    function split_line(line)
        cells = String[]
        cur = Char[]
        inq = false
        i = firstindex(line)
        while i <= ncodeunits(line)
            c = line[i]
            if inq
                if c == '"'
                    if nextind(line, i) <= ncodeunits(line) && line[nextind(line, i)] == '"'
                        push!(cur, '"')
                        i = nextind(line, i)
                    else
                        inq = false
                    end
                else
                    push!(cur, c)
                end
            elseif c == '"'
                inq = true
            elseif c == ','
                push!(cells, String(cur))
                empty!(cur)
            else
                push!(cur, c)
            end
            i = nextind(line, i)
        end
        push!(cells, String(cur))
        return cells
    end
    lines = readlines(path)
    header = split_line(first(lines))
    return map(lines[2:end]) do ln
        cells = split_line(ln)
        Dict(header[j] => strip(cells[j]) for j in 1:min(length(header), length(cells)))
    end
end

The pre-registered protocol — what was frozen, and when

The protocol (.planning/phases/42-thesis-case-a-magnitude/42-CASE-A-PROTOCOL.md) was committed before any 784-house solve executed; every CSV row this page reads stamps a protocol_sha column (the 40-hex git SHA of the protocol's latest commit at measurement time), so every number below is auditable to the exact protocol version that produced it. The frozen pieces:

  • The gain definition (REPRO-03): ΔW = W_DADP − W_FIT, Δ% = 100·ΔW/|W_FIT| — the naive ratio banned (see the locked statements above).
  • The registered configuration (REPRO-04): :ieee13 feeder, ConvexBranchFlow(), T = 24, λ₀ = build_price(:mem), allow_export = true, the :case_a_784 population (784 houses → 10 bus-level aggregators), ρ = ADMM().ρ locked, provenance stamped on every row (julia_version, threads, blas_threads, seed, t_horizon).
  • The seeds: master seeds 42 (the registered continuity anchor) … 46 — each a full honest re-draw via the POP-02 hash seeding.
  • The AGR solver-precision ladder: default → gap_1e-10 → gap_1e-12 → gapfeas_1e-12, stop-on-first-certified, hard stop after the last rung — the ONLY answer to a refusal; no gate was ever loosened.
  • The four ablation axes (REPRO-05): fitparams, pricerange, population, device_mix — axis names AND variant values committed pre-run; no free-form search.
  • The amendment policy: the protocol file is append-only after the pre-run commit; the ONE amendment (2026-10-26) repaired the gapfeas_1e-12 rung's Clarabel attribute spelling (tol_feas; the pre-registered tol_feas_abs/rel field names do not exist in Clarabel 0.11.1) — name, ladder position and hard-stop unchanged; no gate, no ρ, no battery τ touched.
