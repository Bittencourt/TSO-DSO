Flexibility market vs price coordination

This page compares two ways a DSO can coordinate aggregators on the same feeder and the same population: price-based coordination through the dynamic distribution price (DADP), and a two-stage DSO flexibility market. The measurement is produced by scripts/tariff_comparison.jl and committed to results/settlement_comparison/:

julia --project=. scripts/tariff_comparison.jl --mode ieee13-ground --flex-market
julia --project=. scripts/tariff_comparison.jl --mode ieee123 --flex-market
julia --project=. scripts/tariff_comparison.jl --mode ieee123-default

This page solves nothing. It reads the committed tariff_comparison.csv (and the per-hour rebound_hourly.csv) and recomputes every quoted number live from those rows, so no result below is typed by hand. The CSVs carry no run-date column; the provenance printed below is what every row stamps (Julia version, seed, horizon, thread counts), and the date of a measurement is the commit that recorded its rows.

The library side is src/coordination/ (the scheme types, bid generation, the stage-2 clear and the settlement) and the opt-in flex_market keyword of compare_tariffs.

The reader below is copied from the settlement page: it is quote-aware, because the recorded status messages contain commas and quotes, and an EMPTY cell (a deliberately missing value) parses to NaN, never silently to zero.

function read_settlement_csv(path)
    function split_line(line)
        cells = String[]
        cur = Char[]
        inq = false
        i = firstindex(line)
        while i <= ncodeunits(line)
            c = line[i]
            if inq
                if c == '"'
                    if nextind(line, i) <= ncodeunits(line) && line[nextind(line, i)] == '"'
                        push!(cur, '"')
                        i = nextind(line, i)
                    else
                        inq = false
                    end
                else
                    push!(cur, c)
                end
            elseif c == '"'
                inq = true
            elseif c == ','
                push!(cells, String(cur))
                empty!(cur)
            else
                push!(cur, c)
            end
            i = nextind(line, i)
        end
        push!(cells, String(cur))
        return cells
    end
    lines = readlines(path)
    header = split_line(first(lines))
    return map(lines[2:end]) do ln
        cells = split_line(ln)
        Dict(header[j] => strip(cells[j]) for j in 1:min(length(header), length(cells)))
    end
end

1. Two coordination schemes

Price-based (DADP). One centralized social-welfare solve on the SOCP branch-flow model, certified by the exactness gate. Its nodal-balance duals are the distribution prices, and each aggregator responds to its own bus price. In the code this is PriceBased().

Flexibility market. FlexMarket(; baseline_tariff, payment_rule, n_blocks, baseline_inflation) runs two stages:

  1. Baseline. Each aggregator dispatches as a price-taker against a revenue-neutral retail tariff derived from the same DADP run: the flat tariff by default, TOU as an option. That schedule is the baseline b.
  2. DSO redispatch. On the same feeder, the same SOCP model and the same exactness gate, the DSO buys activated up and down quantities from the aggregators' bids to minimise the cost of accepted bids plus the wholesale import cost λ₀ᵀ p_import.

The bids are divisible, piecewise-linear and hour-separable: n_blocks up and n_blocks down blocks per aggregator and hour (4 each by default). Each aggregator builds them by probing its own model: single-hour perturbation re-solves around the baseline, with the other hours held at baseline. The block price is the aggregator's own utility loss, so the bids are truthful by construction and the marginal cost is non-decreasing.

Because a single-hour bid cannot carry intertemporal coupling (battery state of charge, deferrable energy), each aggregator then re-solves to track its activated targets b + Δ. The delivered dispatch is what gets settled, valued and AC-checked, and the delivery shortfall |delivered − (b + Δ)| is reported (section 8).

Reactive power in stage 2 is held at the inelastic draw −Pdc·tanφ. The flex product is active power only, and the bid pseudo-device writes no reactive injection. Two reasons make this the right reading rather than a simplification of convenience: it is the same reactive model the AC feasibility check uses, so stage 2 and the AC verdict see the same q; and holding q at the full baseline value instead (which includes the flexible-load draw p·tanφ at the low flat price) makes the redispatch infeasible on these feeders. The documented difference from DADP is that the centralized DADP solve includes the flexible-load reactive draw and stage 2 does not. A population with a constant reactive injection (FixedCapacitor) or with a device that has its own reactive decision (SmartInverterPV, FourQuadBESS) is refused before any solve, because the pseudo-device cannot represent it. Flexible loads are not refused: their power-factor draw is exactly the term stage 2 drops on purpose.

2. First-welfare-theorem framing (read this before any number)

With truthful, convex, divisible bids that equalled each aggregator's exact separable loss, the stage-2 optimality conditions would coincide with those of the centralized welfare solve: an accepted marginal block prices at the clearing price, and the network conditions are the same. The uniform clearing price would then equal the DADP price and the market welfare would equal the DADP welfare. This is the first-welfare-theorem (LP-duality) analogue of a competitive market.

The bids used here are a finite set of blocks (bid discretisation) and are hour-separable approximations of a value function that is coupled across hours (hour separability). The measured welfare gap is therefore the bid-discretisation plus hour-separability gap, not a property of markets in general. It is printed below in the like-for-like (lossless) convention explained in section 3, absolute and relative to the DADP welfare on the same footing.

let
    for mode in FLEX_MODES
        for r in filter(x -> x["mode"] == mode && isflex(x), summary_rows)
            r["status"] == "ok" || continue
            num(r["baseline_inflation"]) == 0 || continue
            gap = num(r["welfare_gap_vs_dadp_lossless"])
            ref = num(r["welfare_dadp_lossless"])
            verdict =
                gap == 0 ? "NULL (exactly zero)" :
                (gap < 0 ? "flex below DADP" : "flex above DADP")
            @printf(
                "%-14s %-13s  welfare_gap_vs_dadp_lossless = %+.4f  (relative %+.3e)  -> %s\n",
                mode,
                r["tariff"],
                gap,
                gap / abs(ref),
                verdict
            )
        end
    end
end

A likely reason is that the dual of a stage-2 balance over piecewise-linear bids sits at a block price, which can jump between blocks while the welfare barely moves; this is not separately measured here.

3. Welfare convention: lossless vs lossy

Every welfare number is social welfare recomputed from utilities, never an objective value: device utilities minus the wholesale cost λ₀ᵀ p_import. The flexibility-market welfare is evaluated on the delivered dispatch with the lossless import −Σ_j n_j[t], the same convention as the flat and TOU legs: the delivered dispatch comes from device-level re-solves that carry no network state. The DADP welfare uses its own loss-inclusive SOCP import.

A naive comparison therefore credits the flexibility market with the DADP loss cost and can show "flex above DADP". The like-for-like column welfare_gap_vs_dadp_lossless re-evaluates the DADP dispatch on the lossless footing (welfare_dadp_lossless) before subtracting. Both gaps are printed below; the difference between them is the DADP loss cost.

4. Payment rules: the dispatch is identical, only money moves

  • Uniform: activated flexibility at a bus and hour is paid the clearing price, the dual of the stage-2 nodal balance at that bus and hour.
  • Pay-as-bid: each activated block is paid its own bid price times its quantity.

The physics is computed once per clear and shared by both rules, so welfare, the AC verdict and the delivered dispatch are equal; the rows differ in the ledger only. The DSO pays the flexibility payments to the aggregators as mirrored transfer pairs in the same settlement ledger as the tariff legs, so the ledger still sums to zero exactly.

With strategic bidders the comparison would change (bidders shade their bids up under pay-as-bid); that is out of scope here (section 12).

5. Tariff on activation

The settlement charges the baseline tariff on all metered (delivered) energy and pays flexibility on the activated deviation Δ. An up-activated unit is therefore billed the tariff for the energy it consumes and paid the clearing price for having moved, so relative to a baseline-settled design it earns tariff + clearing price. This is standard local flexibility market practice: retail energy and the flexibility service are settled separately. The column tariff_on_activation = Σ p_t·Δ_{j,t} quantifies the overlap. It moves money only; dispatch and welfare are unaffected.

6. Why the market activates: congestion vs energy mispricing

A flat-baseline market activates for two reasons that must not be confused:

  • Congestion relief: the baseline overloads a branch or a voltage limit, and stage 2 buys the deviation that removes it.
  • Energy mispricing: the flat tariff is far from the wholesale price λ₀, so the baseline misallocates energy across hours, and stage 2 (which minimises cost at λ₀) buys back the energy value even in hours without any binding network limit.

An hour counts as congested when the congestion and voltage-drop components of the stage-2 price decomposition exceed κ·λ₀[t] at some bus, with κ = 1e-2. The reported interval [κ_lo, κ_hi) is the measured range of thresholds that give exactly the same set of hours, so the count is robust to the choice of κ across that whole interval.

The flat level is recovered from the CSV: under a flat baseline p_t is one constant, so p = tariff_on_activation / (flex_up_total − flex_down_total). The mean of λ₀ is computed from the same price generator the script uses: build_price(:mem, 24, nothing) for IEEE-13 (the script's ground_setup), and the script's own ieee123_lambda0() profile for IEEE-123, parsed from scripts/tariff_comparison.jl (not retyped here).

7. Baseline gaming via β

A flexibility market settles against a baseline the seller reports. The opt-in baseline_inflation = β models the classic manipulation: the reported baseline is the true baseline times (1 + β) on the up direction in congested hours (only positive consumption baselines are inflated). β changes payments only, never physics: the dispatch, the welfare and the AC verdict are those of the truthful clear, and each row reports the overpayment against the true baseline.

let

                all(r -> r["welfare"] == rs[1]["welfare"], rs) &&
                all(r -> r["max_overload_ratio"] == rs[1]["max_overload_ratio"], rs)

                mode,
                rule,
                join((r["baseline_inflation"] for r in rs), " / "),

                same_physics

On IEEE-13 the overpayment is linear in β: a seller who inflates its baseline by 10 % is paid for flexibility it never provided, at no physical cost. On IEEE-123 the overpayment is zero at every β, for a structural reason rather than robustness (section 10): the only congested hour is a reverse-flow export hour, where the baselines are negative and nothing is inflated.

Baselines are a known weak point of local flexibility markets. The EcoGrid 2.0 field trial (Heinrich, Ziras, Syrri and Bindner, Applied Energy 261, 2020) reports real-life baseline problems for DSO services, and Ziras, Heinrich and Bindner, "Why baselines are not suited for local flexibility markets" (Renewable and Sustainable Energy Reviews 135, 2021), propose capacity-limitation services instead. The β rows quantify that exposure on this model; they are an exogenous sensitivity, not a model of strategic behaviour.

8. Hour-separability shortfall

The bids are hour-separable, but the devices are not: a battery that discharges more in one hour has less energy for the next. The delivery re-solve tracks the targets b + Δ with a fixed, documented L1 penalty weight w, and whatever it does not reach is the delivery shortfall. It is reported, never hidden: total, worst single bus-hour, and ratio to Σ|Δ|.

The weight rule, ten times the largest price in play, is a heuristic and not a proof that the penalty is exact. The penalty is exact only when w exceeds the multiplier of the tracking constraint, and that multiplier is a device's marginal utility at its target minus the tariff, bounded by the slope of the device's value function there rather than by any price. A steep utility, or a coupled device near the edge of its reachable set, can push it above w. What is guaranteed is weaker: the total shortfall does not increase with the weight, so the total at w is an upper bound on the loss that hour separability alone causes. That bound has three limits. It holds for totals only (over all aggregators, or for one aggregator), not for the worst bus-hour or the per-hour shortfall, which can rise while the total falls. It is relative to the relaxed battery model, so it bounds the physical loss only where the delivered battery certificates are :ok, as they are on every committed ok flex row. And "does not increase" holds only up to solver tolerance, which is the size of the committed 10w changes printed below.

The baseline is a different matter. The stage-1 flat-price dispatch that every offer is measured from carries its own battery certificates, and on both IEEE feeders some of them are refused: the relaxed battery model is not exact at that baseline. The baseline is used as computed and the refusals are counted, not repaired. Per feeder, baseline refusals next to the delivered ones:

12. Assumptions and limitations

  • Truthful bidding. Every block is priced at the aggregator's own utility loss. No bid shading or markup is modelled, so the pay-as-bid result is the truthful-bidder lower bound on payments, not a prediction under strategic bidding.
  • Exogenous β only. Baseline inflation is a fixed sensitivity parameter, not a strategic choice.
  • No market power. Aggregators are price-takers in both stages.
  • Hour-separable, divisible bids. No indivisible or binary blocks, and no intertemporal coupling inside a bid; the delivery shortfall (section 8) measures the cost.
  • Heuristic tracking weight. The delivery penalty weight is ten times the largest price in play, not a proven bound on the tracking multiplier, so the reported total shortfall is an upper bound on the hour-separability loss (totals only, relative to the relaxed battery model, up to solver tolerance); the 10w column measures its sensitivity (section 8).
  • Refused baseline battery certificates. The flat-price baseline that offers are measured from is not battery-exact on either IEEE feeder; the refusals are counted, not repaired (section 8).
  • Clearing prices are not DLMP estimates on the IEEE feeders: the gap to the DADP price is far outside the two-bus band (section 2).
  • Inelastic reactive power in stage 2 (section 1).
  • Devices with their own reactive decision are refused in stage 2 (SmartInverterPV, FourQuadBESS; section 1).
  • The V2G EV certificate is reported separately. The price-taker baseline and the delivery record an EV co-charge status of their own beside the battery status. Like the battery refusals it is counted, never repaired, and it is checked at the tolerance of the ADMM final consolidation.
  • Actors are not settled here. Settling profit-seeking aggregator actors (Portfolio with a ProfitObjective) through the flexibility market or the tariff comparison is a recorded scope decision, left to future work (wedge lines and flexibility payments in one ledger with residual 0). clear_flex_market and compare_tariffs refuse any actors value other than nothing with an ArgumentError, before any solve. A SettlementInput built from an actor run is not detected, so its wedges are not carried into this ledger.
  • Lossless flex welfare against loss-inclusive DADP welfare; use the like-for-like column (section 3).

13. Reproduce

julia --project=. scripts/tariff_comparison.jl --mode ieee13-ground --flex-market
julia --project=. scripts/tariff_comparison.jl --mode ieee123 --flex-market   # several minutes
julia --project=. scripts/tariff_comparison.jl --mode ieee123-default

The ieee13-ground flex path first checks that the in-run DADP row reproduces the committed one bit for bit and writes nothing otherwise. Rows are upserted by provenance, and a run first deletes the rows of its own mode that it owns, so a re-run replaces its own rows, leaves no stale ones beside them, and keeps the others:

  • an IEEE-123 run owns every row of its mode, so the committed ieee123 artifact is recorded with --flex-market (a base-only run deletes the flex rows);
  • the default ieee13-ground run owns the base rows; it also owns the flex rows, and deletes them, when its dadp row no longer reproduces the committed one or when the run is refused;
  • the ieee13-ground flex path owns only the flex rows, and so does its --record-timeout S --flex-market record of a stopped flex run (one flex_(run) row);
  • a plain --record-timeout S records a stopped base run and owns every row of the mode.

The fast item "flex market: committed comparison CSV rows" in test/test_flex_market_ieee.jl checks the committed rows' invariants (statuses, no run-level row beside leg rows, β changes money only, the shortfall sums).
