Settlement, Tariffs & Equity — the per-actor ledger and its comparison

This page documents the settlement layer (src/settlement/): how any solved run is settled into a per-actor money ledger that sums to zero with an EXPLICIT merchandising- surplus line (SETL-01); how flat and TOU tariffs are DERIVED revenue-neutrally from one DADP run and compared against FIT and nodal-DADP on the SAME network and population, with per-tariff counterfactual dispatch, AC-physics feasibility statuses, equity metrics and rebound (SETL-02, SETL-03, SETL-06); and how equity is broken out by PV ownership, electrical location and load level (SETL-05) — with the no-income-data statement below.

The computational pieces each carry their own test certificate (test/test_settlement.jl, test/test_equity.jl); this page executes a tiny live slice so the rendered numbers cannot drift from the real src/ code, and reads the committed measurement CSVs in results/settlement_comparison/ for the heavy 784-house results (the precomputed- results precedent of the Case-A population and IEEE-8500 scaling pages).

No income data — the locked statement

Every equity number in this framework operates on per-household BILLS and SURPLUS only. NO income data exists in this framework and none is used anywhere. The proxy groupings (PV owner vs non-owner, electrical location, load-level terciles of baseline consumption) come from the case_a_household_map row shape — house, bus, aggregator, device set, PV group, house index — no new data, and never an income variable. This is the phase's locked deliverable (SETL-05), stated at module level in src/settlement/equity.jl and repeated here because it qualifies every chart the equity metrics will ever produce.

The live slice — one DADP run settled end-to-end (seconds)

The block below solves the 2-bus welfare fixture, packs it into a SettlementInput, settles the double-entry ledger, derives the revenue-neutral flat and TOU prices, re-dispatches a price-taker at the run's own prices, checks the AC physics of that dispatch, and computes the four equity metrics on the ledger's household rows. Total runtime: a few seconds (T = 3, two buses, two houses).

The 784-house comparison — read from the committed CSVs

This section reads committed data; nothing heavy is solved at build time

The full comparison runs per mode through the measurement script. Regenerate with:

julia --project=. scripts/tariff_comparison.jl --mode ieee13-ground
julia --project=. scripts/tariff_comparison.jl --mode case-a-784   # long-running

The script UPSERTS its rows into results/settlement_comparison/*.csv keyed on provenance (mode, tariff, seed, t_horizon) — re-runs replace their own rows and never drop others'. A killed run leaves the rows already captured — a kill is a MEASURED OUTCOME (honesty policy), and so is every per-leg status row: a leg whose certified values are missing is RECORDED, never dropped.

The minimal reader below is quote-aware (the recorded status messages legitimately contain commas and quotes); an EMPTY cell is a deliberately-missing certified value and parses to NaN — never silently to zero.

function read_settlement_csv(path)
    function split_line(line)
        cells = String[]
        cur = Char[]
        inq = false
        i = firstindex(line)
        while i <= ncodeunits(line)
            c = line[i]
            if inq
                if c == '"'
                    if nextind(line, i) <= ncodeunits(line) && line[nextind(line, i)] == '"'
                        push!(cur, '"')
                        i = nextind(line, i)
                    else
                        inq = false
                    end
                else
                    push!(cur, c)
                end
            elseif c == '"'
                inq = true
            elseif c == ','
                push!(cells, String(cur))
                empty!(cur)
            else
                push!(cur, c)
            end
            i = nextind(line, i)
        end
        push!(cells, String(cur))
        return cells
    end
    lines = readlines(path)
    header = split_line(first(lines))
    return map(lines[2:end]) do ln
        cells = split_line(ln)
        Dict(header[j] => strip(cells[j]) for j in 1:min(length(header), length(cells)))
    end
end

How to read the table, leg by leg:

  • dadp — the run itself: the welfare-optimal dispatch settled at its own nodal prices. Its fairness_total column (not printed above) IS its settlement: the revenue-neutrality baseline every derived tariff must reproduce.
  • flat / tou — revenue-neutral DERIVATIONS (41-03's tested constructors, same input) re-dispatched through the penalty-free price-taker QP (all devices, batteries included). Their fairness_total equals the dadp settlement within measured rounding dust (pinned rtol 2.8658034134118547e-15 / 1e-15 in test/test_settlement.jl), so the comparison isolates DISPATCH behavior, not tariff revenue. A solve_failed feasibility verdict means the counterfactual dispatch has NO AC operating point on this feeder (beyond loadability) — a recorded diagnostic, never a dropped leg.
  • fit — fit_baseline consumed as-is (golden). On the congestion-calibrated IEEE-13 fixtures the batteryless (A4) FIT dispatch is genuinely INFEASIBLE against the head-branch thermal rating (attributed by probe: lifting only the head smax makes fit_baseline converge) — recorded as an honest error row with the non-certified values missing.

Metric conventions — the negative-value treatment, restated

Each metric's full convention lives in its docstring (src/settlement/equity.jl) and is certified by hand-computed known-value tests (test/test_equity.jl, including the exact negative-bearing Gini 0.8125 and the uniform anchor (0, 0, 0, 0.25)). The short forms, which every table above inherits:

MetricConventionNegative-value behaviour
Ginipopulation mean-absolute-difference form over ALL valuesa relative mean-difference measure, NOT a concentration index — may exceed 1 and may be negative on net-earning populations; values are NEVER zeroed or dropped (the documented bias finding)
Theil(1/n) Σ (x/μ) ln(x/μ) on the positive-support subsetnon-computable for x ≤ 0 — the excluded count is a RETURNED value (theil_n_excluded columns), all-excluded ⇒ NaN, never a fake zero
Atkinson1 − (Σ x^(1−ε)/n)^(1/(1−ε)) / μ on the positive-support subset, ε = 0.5same positive-support restriction with the excluded count returned; ε = 1 (the log form) is deliberately unimplemented
PalmaΣ(top 10 %)/Σ(bottom 40 %) over the sorted FULL vectorgroup totals cancel, so it is the most negative-robust; a negative bottom-40 sum yields a negative ratio reported as computed; an exactly-zero bottom sum ⇒ NaN
reboundload shifted into later hours after price-driven reductions, on NET-LOAD profiles (grid consumption = −net injection)battery- and deferrable-driven shifts share one definition; no-reduction input ⇒ ratio NaN (reported), reductions without later increases ⇒ ratio exactly 0.0

The A1 asymmetry — the FIT leg is batteryless, and it shows

The :dadp/:flat/:tou legs settle household equity from per-house price-taker dispatches with ALL devices (batteries included — the rebound metric explicitly requires battery-driven shifts). The :fit leg is fit_baseline consumed as-is, and fit_baseline is BATTERYLESS by design (thesis Assumption A4): it also exposes no per-aggregator device utility. The comparison therefore reports the fit leg's equity at BUS granularity (bills_granularity = bus), with the surplus-side equity columns missing — marked, never hidden, and never back-filled with a different dispatch. On the congestion-calibrated IEEE-13 fixtures the asymmetry is physical: without batteries the FIT schedule's PV export cannot clear the head-branch thermal rating, and the leg is recorded as a genuine infeasibility.
